Release notes

CoreChatX 2026.3.0

All player and administrator changes since 2026.2.6.

Upgrade instructionsYAML to MySQL migration

Added

  • Added optional MYSQL runtime storage for standalone Paper and Velocity, covering player preferences, nicknames, statistics, active and hidden channels, ignores, mutes, global state, Discord links, unlink records, and pending link codes. YAML remains the default; Velocity owns shared data separately for each network group.
  • Added /ccxstorage on Paper and Velocity for storage health, file/database validation, checksummed backups and verification, migration planning, parity checks, transition history, resume, and abort. Migration and rollback use confirmation tokens and durable journals; incomplete transitions keep affected gameplay storage unavailable until recovery is completed.
  • Added the Channel compass in /ccxsettings and /chatsettings. Each player can choose Persistent (the existing default) or Non persistent, which returns to the configured default channel on the next connection, including after a server restart. Changing this option keeps the current channel, and proxy backend transfers preserve it during the same connection.

Changed

  • Storage-backed settings, nickname, channel, ignore, and moderation changes now wait for the authoritative result before reporting success. Concurrent single-setting updates preserve unrelated preferences, /ignore and /unignore apply the requested final state, and ignore limits are checked against the saved list. A response timeout does not mean an accepted database write was cancelled.
  • With MYSQL, Paper loads complete player state before admission; gameplay storage remains unavailable until database startup and ownership checks succeed. MySQL failures do not silently switch the installation back to YAML. A database lease prevents two live processes from writing the same storage scope.

Fixed

  • Fixed /ccxstorage migrate files-to-mysql abort deleting data that a planned or failed run had never imported. Aborting an imported run now refuses to delete rows if their current content differs from the verified source, and cancelling an older failed run preserves later imports.
  • Fixed storage recovery accepting a migration run ID from another namespace or scope. Run IDs now apply only to the configured storage owner, preventing cross-group changes.
  • Fixed Paper treating malformed persistent YAML as empty data and later overwriting the original files. Startup now reports the error; after a failed player/global reload, writes and shutdown flushes remain blocked until the file is repaired and successfully reloaded.
  • Fixed delayed proxy mute lookups clearing a newer mute or making it appear permanently cleared in a backend cache.
  • Fixed public chat and private messages being allowed before a proxy backend had loaded the player's mute state. With mute enforcement enabled, messages receive temporary-unavailability feedback until the authoritative lookup completes.
  • Fixed simultaneous nickname changes assigning the same visible name to different players on Velocity with YAML. Full player updates and /nick changes now enforce the same normalized name ownership atomically.
  • Fixed Discord linking instructions showing /link when the bot uses a custom command. Minecraft link-code help, required-link admission messages and Discord DMs now use the configured name on standalone Paper and Velocity networks.
  • Fixed the first inbound Discord message displaying an unresolved linked-player nickname in proxy mode before the player's state had been loaded.
  • Fixed delayed asynchronous completions overwriting newer player settings, channels, statistics, mutes, global state, or Discord link/unlink data. An old player's quit cleanup no longer discards a newer login's hydrated state, and pending Discord-code reads cannot restore codes invalidated by newer changes.
  • Fixed /chatmute updates overwriting the first-join counter, and concurrent settings or ignore changes replacing unrelated saved values.
  • Fixed /corechatx reload temporarily reverting proxy player preferences or showing empty statistics. Reload retains hydrated mirrors and pending storage requests, then refreshes cached/online state after transport registration to recover changes missed while networking was unavailable. Restart-only deployment and storage identity changes retain the active boot configuration until restart.
  • Fixed concurrent YAML saves allowing older snapshots to replace newer data; write failures now propagate through the storage operation. Maintenance waits for accepted writes, including those whose callers already timed out, before migration or rollback proceeds.
  • Fixed MySQL ownership checks when a write waits on a database lock until its lease expires, and shutdown handling for queued operations and late completions, preventing expired owners from writing and callers from remaining pending indefinitely.
  • Fixed item dragging into the temporary /ccxsettings inventory, which could lose deposited items when the menu closed.
  • Fixed cross-server private-message timeouts silently removing pending deliveries without notifying their senders; expired deliveries now notify each affected sender once.
  • Fixed inbound bridge and outbound Telegram length limits splitting an emoji's UTF-16 pair at the truncation boundary.
  • Fixed mandatory Discord linking admitting unlinked players when the bot/link commands were unavailable or link-code creation failed. account-linking.require-linked-to-play now denies entry with a temporary-unavailability message; Velocity enforces it before backend entry. deny-if-unverifiable still controls role verification for already linked players and cannot bypass the mandatory link.
  • Fixed Discord's Velocity console missing feedback sent through current or typed Adventure message calls.
  • Reduced resource-pack fingerprint string copying during Discord ChatItem image initialization, addressing avoidable work during Paper startup and reload while preserving the existing cache fingerprint format.
  • Fixed Paper startup and /corechatx reload waiting on Discord token verification or gateway shutdown on the server thread. Discord reconnects asynchronously; retired connections and queued role callbacks cannot reactivate the previous bridge.
  • Fixed /ccxstorage migration or rollback retries failing after a successful abort because the previous journal was treated as a completed cutover. Verified aborts can be retried without deleting journals; Velocity also supports aborting plans before execution and repeating an interrupted abort safely.
  • Fixed MySQL startup deadlocks when independent network groups initialize new storage scopes concurrently. Duplicate owners of the same scope are still rejected.
  • Fixed ordinary YAML saves after MySQL-to-YAML rollback dropping runtime-updated-at, which could regress a player's saved aggregate version and break canonical backup parity.
  • Fixed linked Discord messages being dropped on standalone MySQL after the Minecraft sender disconnected or the server restarted. Offline nickname and staff checks now read saved settings asynchronously, honor allow-offline-linked-players, and deny delivery when authoritative settings are unavailable.
  • Fixed startup checksum mismatches caused by changed line endings in packaged MySQL migration files. The JARs preserve the existing migration bytes; do not edit database checksums to bypass validation.

Configuration

  • Added {link_command} (the Discord command name without /) to linking messages. Use /{link_command} code:{code}; it reads account-linking.link-command-name from the standalone bot or the Velocity authority. Exact older stock messages are adapted automatically; add the placeholder manually to customized messages.
  • Added active MySQL configuration in Paper storage.yml and Velocity velocity-storage.yml: storage.backend, stable namespace/scope identity, connection and TLS settings, bounded pool/executor and operation timeouts, leases, and schema-auto-migrate. Use storage.mysql.password-env to supply credentials from an environment variable; the default TLS mode is VERIFY_IDENTITY.
  • Added the saved player preference persistent-channel-enabled, defaulting to true for existing data, plus link-check-unavailable-kick under Paper's Discord messages and Velocity's account-linking messages.

Permissions

The op default below applies to Paper. On Velocity, grant the node through your proxy permission provider.

  • Added corechatx.command.storage with default op for storage inspection and backups. Migration and rollback state changes remain console-only, including for operators; Velocity transitions require explicit --all-scopes confirmation.

Compatibility

  • Paper and Velocity runtime JARs now include the required MySQL runtime and JDBC driver. Install only the appropriate platform JAR; no separate storage-module, HikariCP, or Connector/J installation is needed. YAML-only setups do not need a database.

Migration

  • Before updating, stop the affected servers and back up every file and subfolder in the CoreChatX plugin folders, including configuration, player data, credentials, journals, and existing backups. Preserve the old JARs separately; with MySQL, also retain a database backup.
  • The website now includes a step-by-step migration guide from 2026.2.6 YAML to 2026.3.0 MySQL for standalone Paper and Velocity networks, covering backups, configuration, verified migration, activation, rollback, and interruption recovery.
  • Upgrade Velocity and every participating Paper backend together. The current plugin-message protocol is 29; mixed older/newer JARs cannot exchange the complete runtime state and mutation requests reliably.
  • Legacy storage.sql.* settings never enabled a database and still do not select MySQL. Configure storage.backend: MYSQL and the current storage.mysql.* keys. For existing YAML data, use /ccxstorage migrate files-to-mysql plan and its confirmed execute/restart workflow; changing the backend setting alone does not migrate data.
  • MySQL schema V003 adds the channel preference with existing players defaulting to persistent channels. With schema-auto-migrate: false, arrange the required schema upgrade before startup. Older builds reject schema version 3; replacing the JAR with an older version is not a database downgrade.
  • After an abort, keep the corrected 2026.3.0 JARs: earlier builds do not recognize the new ABORTED local journal state. Use the new plan's run IDs and confirmation tokens; never remove journals or alter checksums to force a retry.
  • Use /ccxstorage rollback mysql-to-files to export the latest database state before returning to YAML. Do not overwrite newer MySQL data with a pre-migration YAML backup. Existing canonical format 1 backups remain readable; snapshots containing a non-persistent channel preference use format 2, which requires the matching newer build to restore that preference.

Known issues

  • Proxy player-state reads on a backend can briefly show its last confirmed data while an asynchronous refresh is pending; do not treat a cached read as proof that a new remote write has completed.
  • Discord can delay channel-topic updates after rapid joins or restarts because of its rate limits; chat and account linking continue while topic updates are retried.
  • The 2026.2.6 migration was exercised with synthetic legacy data, not a production dataset. Rehearse against an isolated copy of your data and retain complete backups before production cutover.
