Chat formatting

Use one formatter to control player names, rank prefixes, colors, and message layout.

EssentialsX Chat

Used for: Group-based chat formats, prefixes, suffixes, and colors in the EssentialsX suite.

How CoreChatX replaces this use: CoreChatX can take over public-chat formatting through chat.yml, LuckPerms rank prefixes, primary-group formats, and optional PlaceholderAPI values. Channel-specific formats live in channels.yml.

Scope and differences: This replaces the chat-formatting role. Keep EssentialsX if you use its homes, warps, economy, kits, or other commands. Recreate formats with CoreChatX placeholders; the EssentialsX Chat configuration is not imported.

Official project documentation · CoreChatX setup and features

LPC / LuckPermsChat

Used for: Chat formatting with LuckPerms prefixes, group formats, RGB colors, and PlaceholderAPI support.

How CoreChatX replaces this use: CoreChatX can replace this formatter using public-chat.format and public-chat.group-formats in chat.yml. It reads LuckPerms metadata and supports MiniMessage templates.

Scope and differences: LuckPerms stays installed to manage permissions and ranks. Rebuild LPC templates and check any world or server contexts you rely on; the two plugins do not share a configuration format.

Official project documentation · CoreChatX setup and features

DeluxeChat

Used for: Configurable chat formats with hover and click actions, placeholders, private messaging, and BungeeCord options.

How CoreChatX replaces this use: CoreChatX covers formatted public chat, MiniMessage hover/click actions, and /msg / /reply. Group and channel formats define the layout; network messages run through the CoreChatX Velocity setup.

Scope and differences: Convert formats manually. DeluxeChat format-priority permissions and recipient-dependent relational placeholders are not interchangeable with CoreChatX primary-group formatting. A BungeeCord installation must move to a supported Velocity setup for CoreChatX network chat.

Official project documentation · CoreChatX setup and features

ChatEx

Used for: Chat prefixes and suffixes, join/quit messages, word controls, chat clearing, and other chat-management features.

How CoreChatX replaces this use: CoreChatX covers the chat-formatting role, customizable join/quit messages, word censoring, repeat checks, and /clearchat. Configure these in chat.yml, messages.yml, filter.yml, and moderation.yml.

Scope and differences: ChatEx also documents tab-list prefix/suffix formatting and advertisement blocking. CoreChatX chat formatting does not replace a tab-list manager or a dedicated advertisement detector.

Channels and network chat

CoreChatX uses Paper for standalone servers and Paper plus Velocity for networks. Network channels and private messages stay inside the configured CoreChatX network group.

VentureChat

Used for: Public and private channels, local-distance chat, network channels, permissions, formatting, and moderation tools.

How CoreChatX replaces this use: CoreChatX can take over global, local, staff, and custom channels with separate send/receive permissions. Use NETWORK, SERVER, or LOCAL_RADIUS in channels.yml; private messages and social spy are included.

Scope and differences: CoreChatX uses a different channel and permission model. Its player mutes do not reproduce VentureChat's per-channel mute model, and /clearchat is not selective removal of individual messages. Rebuild channel access and use the supported Velocity topology.

Official project documentation · CoreChatX setup and features

HuskChat

Used for: Proxy or standalone chat with channels, private messages, spy tools, filters, and configurable formatting.

How CoreChatX replaces this use: CoreChatX covers channels, one-to-one /msg and /reply, staff social spy, cooldowns, and configurable word censoring. Install CoreChatX on Velocity and each connected Paper backend for network use.

Scope and differences: HuskChat group DMs and its machine-learning profanity checker are separate features that CoreChatX does not reproduce. Move MineDown formats to CoreChatX MiniMessage templates. A proxy-only HuskChat deployment needs Paper-side CoreChatX jars as well.

Official project documentation · CoreChatX setup and features

Carbon Chat

Used for: Configurable channels, local chat, network messaging, ignores, mutes, item links, and player mentions.

How CoreChatX replaces this use: CoreChatX covers those communication roles with channel scopes, player privacy controls, moderation, ChatItem previews, and mentions. Velocity routes messages between Paper servers in the same CoreChatX group.

Scope and differences: Carbon's Redis/NATS/RabbitMQ transport, party system, and dedicated Towny, FactionsUUID, or mcMMO channels are not CoreChatX features. Permission-based channels do not automatically recreate town, faction, or party membership.

Chat moderation

CoreChatX combines player mutes, chat-wide muting, cooldowns, repeat/caps checks, and configurable word censoring. More specialized moderation rules need a separate assessment.

ChatControl

Used for: Chat channels, formatting, moderation, and a broader rules system with custom actions and integrations.

How CoreChatX replaces this use: CoreChatX can replace the channel, formatting, private-message, social-spy, and basic chat-moderation roles. Configure mutes and repeat/caps checks in moderation.yml, cooldowns in chat.yml, and censored terms in filter.yml.

Scope and differences: ChatControl's rule scripts, JavaScript variables, mail, and individual-message removal are not equivalent to CoreChatX features. Keep any required advanced rules covered before replacing it. CoreChatX's word filter censors configured terms and still sends the message.

Chat Manager (Crazy-Crew)

Used for: A chat-management suite with formatting, private messages, staff chat, social spy, and anti-spam tools.

How CoreChatX replaces this use: CoreChatX covers these roles through its formatter, PM commands, permission-restricted staff channel, social spy, cooldowns, and repeat/caps checks. Join/quit text and broadcasts can also be configured.

Scope and differences: Chat Manager includes additional controls such as advertising checks in chat, commands, and signs, and restrictions until a joining player moves. CoreChatX does not provide equivalent sign/command filtering or that movement-based gate.

Item previews and interactive chat

CoreChatX creates temporary item and inventory snapshots when a message is sent, and can render supported previews as images for its own Discord bridge.

ChatItem

Used for: Showing held items to other players through chat.

How CoreChatX replaces this use: CoreChatX covers item sharing with [item] and also provides armor, hotbar, inventory, ender-chest, and shulker previews. Configure token aliases and permissions in chatitems.yml.

Scope and differences: This takes over item sharing inside CoreChatX-managed chat. ChatItem's integrations with other chat handlers are not transferred. CoreChatX previews expire and are cleared on reload; they are not permanent inventory records.

Official project documentation · CoreChatX setup and features

InteractiveChat

Used for: Item, inventory, and ender-chest sharing, plus custom interactive keywords in chat.

How CoreChatX replaces this use: CoreChatX supplies clickable ChatItem snapshots and configurable keywords with hover text, links, commands, or suggestions. Use chatitems.yml for previews and keywords.yml for tokens such as [rules].

Scope and differences: CoreChatX handles its own message pipeline rather than providing an InteractiveChat-compatible API. Recreate custom keywords, permissions, and supported resource-pack settings; existing InteractiveChat extensions are not automatically compatible.

Official project documentation · CoreChatX setup and features

InteractiveChat DiscordSRV Addon

Used for: Bringing InteractiveChat content into DiscordSRV messages, including item/inventory sharing, and sending Discord images or GIFs into Minecraft.

How CoreChatX replaces this use: For Minecraft-to-Discord item and inventory images, CoreChatX combines its own Discord bridge with the discord-images settings in chatitems.yml. Supported snapshots can include menus for inspecting individual items.

Scope and differences: This replaces the outbound preview use case. It does not replace the addon's Discord-image/GIF display inside Minecraft. CoreChatX sends through its own bot integration; it is not a DiscordSRV addon.

Discord bridges and account linking

Choose one integration to own each bridged channel. CoreChatX includes its own bot connection; it does not require DiscordSRV or EssentialsX Discord.

DiscordSRV

Used for: Minecraft/Discord chat, console access, event forwarding, account linking, and further synchronization and voice features.

How CoreChatX replaces this use: CoreChatX covers two-way channel chat, supported server/player events, online lists, console commands/output, account linking, Discord-role admission checks, and Minecraft-to-Discord nickname updates. Configure the bot on standalone Paper or on Velocity for a network.

Scope and differences: DiscordSRV's proximity voice, bidirectional Minecraft-group/Discord-role synchronization, ban synchronization, and addon API are outside this replacement. A CoreChatX role requirement checks access; it does not assign Minecraft permission groups from Discord roles.

EssentialsX Discord / Discord Link

Used for: Discord chat and event bridging, console relay and slash commands; Discord Link adds account-based admission and group/role synchronization.

How CoreChatX replaces this use: CoreChatX covers two-way chat, its supported event notifications, player lists, console controls, account linking, and linked-account or Discord-role requirements for joining. Its bot configuration is separate from EssentialsX.

Scope and differences: CoreChatX does not reproduce Discord Link's bidirectional Vault-group/Discord-role synchronization. Reconfigure channels and link accounts through CoreChatX; existing EssentialsX Discord Link records are not automatically imported.

Communication tools inside larger suites

Keep the rest of an administration suite when you still use it. Only move the communication features you actually want CoreChatX to manage.

EssentialsX — communication commands

Used for: Private messages, replies, nicknames, ignores, social spy, mutes, and broadcasts alongside a much broader server-utilities suite.

How CoreChatX replaces this use: CoreChatX provides /msg, /reply, /nick, /realname, ignore controls, /socialspy, mutes, and broadcasts, using its own saved player data and Velocity network groups.

Scope and differences: This is a partial replacement of EssentialsX. Homes, teleportation, warps, economy, kits, mail, and other utilities stay with their existing provider. Decide which plugin owns overlapping commands; old nicknames, ignores, and mutes are not automatically transferred.

CMI — chat and communication

Used for: Chat formatting, private messages, social spy, mentions, and item sharing within a larger administration and gameplay suite.

How CoreChatX replaces this use: CoreChatX can take over those communication functions with its formats, PM commands, staff spy, mentions, and ChatItem previews. Player preferences and privacy settings are managed through /ccxsettings and related commands.

Scope and differences: This does not replace CMI's economy, portals, kits, holograms, inventory editing, or other administration features. CMI's regex filters and command spying are also separate from CoreChatX's word censoring and PM social spy. Configure ownership of overlapping features explicitly.

Before switching plugins

  1. Back up every file in the affected plugin folders first. Back up any database that contains their saved data as well.
  2. List the features you use. Include formats, channels, commands, permissions, nicknames, mutes, ignores, account links, and any required integrations. Check the differences above against that list.
  3. Recreate the configuration on a separate test server. Follow the Paper or Velocity setup guide. Keep LuckPerms and the PlaceholderAPI expansions needed by your chosen formats. CoreChatX does not replace these providers.
  4. Give each feature one owner. Disable overlapping chat formatters, commands, token handlers, and Discord routes in the plugins you retain. Restart, then check chat delivery, permission restrictions, private messages, previews, and Discord forwarding before moving the setup to your server.

Saved data is a separate step. CoreChatX does not include an automatic importer for the plugins compared here. Its YAML-to-MySQL guide migrates existing CoreChatX data; it does not convert another plugin's nicknames, mutes, ignores, or Discord links.
