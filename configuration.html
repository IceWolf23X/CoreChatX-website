0. Before You Configure

This is the detailed guide for server owners who have installed CoreChatX and want to configure it. If this is your first installation, follow the setup guide first.

What you need:

  • Java 21
  • Paper 1.21.11 for every Minecraft server
  • Velocity only when CoreChatX must connect multiple Paper servers
  • the Paper CoreChatX jar installed only on Paper servers
  • the Velocity CoreChatX jar installed only on Velocity

Optional integrations:

  • LuckPerms for rank prefixes and permission assignment
  • PlaceholderAPI for values such as economy, world, or player statistics in server-created formats
  • a Discord bot token and the required intents if you connect Discord
  • a Telegram bot token if you connect Telegram

Terms used in this guide:

  • Paper server: a Minecraft server running the Paper CoreChatX jar
  • Velocity proxy: the Velocity instance running the Velocity CoreChatX jar
  • STANDALONE: one Paper server without cross-server CoreChatX features
  • PROXY: a Paper server connected to CoreChatX on Velocity
  • server-id: a unique name CoreChatX uses to identify one Paper server
  • network-channel: the CoreChatX group that connects matching Paper servers and Velocity
  • bridge: a connection between Minecraft and Discord or Telegram
  • saved data file: a generated file containing player or plugin data, not a normal settings file

Where features are configured and saved:

  • Paper handles chat formats, commands, ChatItems, bubbles, pings, and the settings files for each Paper server
  • In STANDALONE, Paper also saves player settings, nicknames, ignores, mutes, and Discord links
  • In PROXY, Velocity saves the player data that must follow players between Paper servers
  • Velocity also connects network channels, private messages, player-name suggestions, and remote ChatItem previews
  • configure Discord on Paper in STANDALONE and on Velocity in PROXY; Telegram is configured on Paper in both modes
  • server-created formats can use MiniMessage and supported PlaceholderAPI values
  • players can use only the chat colors and styles allowed by their permissions

Before editing files:

  • configuration files control how CoreChatX works
  • saved data files contain live player and server information
  • back up saved data before editing or deleting it

CoreChatX names and folders

  • Paper plugin name: CoreChatX
  • Velocity plugin ID: corechatx
  • main command: /corechatx or /ccx
  • settings command: /chatsettings or /ccxsettings
  • permission prefix: corechatx.*
  • default network group: corechatx:main

For a clean installation:

  • install corechatx-paper-<version>.jar on Paper
  • install corechatx-velocity-<version>.jar on Velocity
  • keep Paper data in plugins/CoreChatX/
  • keep Velocity data in plugins/corechatx/

When replacing an older or differently named plugin:

  • keep a complete backup of the old plugin folder
  • let CoreChatX create fresh default files
  • copy only settings that still exist in the current reference

2. Reload vs Restart

You can apply these changes with /corechatx reload:

  • config.yml settings other than deployment.mode, deployment.server-id, and deployment.network-channel
  • messages.yml
  • chat.yml
  • pings.yml
  • filter.yml
  • chatitems.yml
  • keywords.yml
  • chatbubbles.yml
  • channels.yml
  • privacy.yml
  • moderation.yml
  • storage.yml
  • discord.yml
  • telegram.yml
  • locale files under locales/

Restart after changing:

  • config.yml -> deployment.mode
  • config.yml -> deployment.server-id
  • config.yml -> deployment.network-channel
  • switching a Paper server between standalone and Velocity mode
  • any Velocity configuration file; Velocity does not have a CoreChatX reload command
  • the Velocity network-channel; every affected Paper server must use the same new deployment.network-channel

Important:

  • Paper servers and Velocity must use exactly the same network group value

Jar files:

  • install corechatx-paper-<version>.jar on each Paper server
  • install corechatx-velocity-<version>.jar on Velocity
  • Do not install the Paper jar on Velocity, and do not install the Velocity jar on Paper.

3. Quick Install Patterns

Standalone Paper

Use the default Paper configuration:

deployment:
  mode: "STANDALONE"
  server-id: "paper-1"
  network-channel: "corechatx:main"
  bridges-allowed: true
  network-features-allowed: false

In this setup:

  • no Velocity jar is required
  • NETWORK channels behave like normal chat on that Paper server
  • private messages cannot cross Paper servers
  • network-wide player suggestions and TAB entries are inactive

Velocity network

On each Paper server:

  • set deployment.mode: "PROXY"
  • set a unique deployment.server-id
  • set deployment.network-channel to the CoreChatX group that server should join
  • set deployment.network-features-allowed: true

On Velocity:

  • install the Velocity CoreChatX jar
  • list every allowed group channel in velocity-config.properties -> network-channel

Example server IDs:

  • alpha
  • beta
  • survival-1
  • hub

With this setup:

  • NETWORK channels and private messages can cross Paper servers
  • player settings are saved by Velocity and follow the player within the same group
  • active channel, pings, private-message availability, social spy, mention notifications, language, staff chat, and ignores can follow server switches
  • player-name suggestions and TAB entries can include players from other Paper servers in the group
  • ChatItems, mentions, and custom pings can work across Paper servers
  • invalid or oversized network messages are rejected

Setup checklist

For a clean standalone Paper install:

  • install only the Paper jar
  • keep deployment.mode: "STANDALONE"
  • keep deployment.network-features-allowed: false
  • configure formats, channels, messages, moderation, ChatItems, keywords, bubbles, and optional integrations on that server
  • restart after changing the mode, server ID, or network group
  • use /corechatx reload for normal wording, formatting, channel, filter, and feature tuning

For a clean Velocity network install:

  • install the Paper jar on every Paper server
  • install the Velocity jar on the proxy
  • set every Paper server to deployment.mode: "PROXY"
  • give every Paper server a unique deployment.server-id
  • set each Paper server's deployment.network-channel to the group it should join
  • include every group in plugins/corechatx/velocity-config.properties -> network-channel
  • set deployment.network-features-allowed: true on each Paper server using cross-server features
  • restart affected Paper servers and Velocity after changing the server ID or network group

When upgrading from 2026.2.0, let CoreChatX create fresh Paper and Velocity configuration files. Then restore your server-specific mode, IDs, groups, channels, Discord token, routes, and required role IDs. In PROXY mode, use the shared player data saved by Velocity instead of copying old Paper player-data files.

For bridge installs:

  • keep deployment.bridges-allowed: true
  • enable only Discord or Telegram features you actually use
  • enable outbound export only on the CoreChatX channels that should leave Minecraft
  • configure incoming routes so Discord or Telegram messages appear in the intended CoreChatX channel
  • in STANDALONE, configure Discord in Paper discord.yml
  • in PROXY, configure the main Discord bot in Velocity velocity-discord.yml
  • in PROXY, Paper discord.yml may still use discord.console.* for that Paper server's console
  • configure Telegram on Paper in both modes

For PlaceholderAPI-heavy installs:

  • install PlaceholderAPI on every Paper server that displays placeholders
  • install the expansions required by your formats
  • use placeholders in server-created formats, not in text written by players
  • placeholders inside a mention use the mentioned player's values
  • test placeholders for offline players before using them in cross-server hover text

For ChatItems on a network:

  • keep ChatItems enabled only on the channels where previews are wanted
  • change data-size limits only when large custom items fail to open
  • leave the default system for loading previews when clicked enabled
  • expired or unavailable previews show the normal expired-preview message

4. Paper Configuration Files

4.1 config.yml

Purpose:

  • deployment mode
  • unique Paper server ID
  • Velocity network group and network feature switch
  • Discord and Telegram master switch
  • PlaceholderAPI and LuckPerms switches
  • logging toggles
  • general reload/save behavior

Current bundled default:

# Core plugin settings.

deployment:
  # STANDALONE = Paper-only mode. Runtime player data is stored in this backend's YAML files.
  # PROXY = Velocity-backed network mode. Runtime player data is owned by the CoreChatX Velocity module.
  # Changing this mode requires a full restart.
  mode: "STANDALONE"
  require-full-restart-on-mode-change: true
  # Backend id used for proxy routing and bridge source labels.
  server-id: "paper-1"
  # Plugin messaging channel shared with the Velocity module.
  # In PROXY mode this also selects the isolated Velocity data/routing group for this backend.
  network-channel: "corechatx:main"
  # Global switch for Discord / Telegram chat bridge runtime.
  # Discord console-only bots may still start through discord.yml -> discord.console.*.
  bridges-allowed: true
  # When false, Paper still boots in PROXY mode but proxy transport is intentionally disabled.
  # Cross-server chat, PM routing, player directory sync, and proxy-owned runtime data operations will not run.
  network-features-allowed: false
  pending-pm-timeout-seconds: 20

debug: false

hooks:
  # If true, PlaceholderAPI placeholders inside CoreChatX config formats are parsed when the plugin is present.
  placeholderapi: true
  # If true, LuckPerms group prefixes are read when the plugin is present.
  luckperms: true

logging:
  public-chat: true
  private-messages: true
  broadcasts: true
  reload: true
  errors: true

player-data:
  # STANDALONE only: toggle commands still save immediately; this mainly controls the fallback save on plugin disable.
  # In PROXY mode player settings, nicknames, ignore lists, active channel, mutes, global state and Discord links are stored by Velocity.
  auto-save-on-disable: true

nicknames:
  # Prefix prepended to {player_nickname} only when the player has a custom nickname.
  # Leave empty to show the nickname exactly as set with /nick.
  # Example: "~" makes {player_nickname} render as ~Nick while {player_name} still renders the real Minecraft username.
  prefix: ""
  # false = /nick can change the visible name text and styling, for example IceWolf23X -> IceWolf.
  # true = /nick can only change allowed colors/styles; the visible text after removing formatting must stay exactly the real Minecraft username.
  # Example with true: IceWolf23X may use &cIceWolf23X, but not &cIceWolf.
  change-only-colors: false
  # false = nickname text may only use A-Z, a-z, 0-9 and _ after formatting is removed.
  # true = CoreChatX does not apply an additional character whitelist to nickname text.
  allow-special-characters: false

first-join:
  enabled: true
  counter-enabled: true

join-quit:
  # LOCAL = announce only on the current Paper backend.
  # NETWORK = in PROXY mode, Velocity owns true network join/leave announcements and uses velocity-messages.yml.
  mode: "LOCAL"
  join-enabled: true
  quit-enabled: true

reload:
  # A short summary is shown to the command sender after a successful reload.
  show-summary: true

What to know:

  • deployment.mode, deployment.server-id, and deployment.network-channel require restart
  • the startup log shows the CoreChatX version, platform, selected mode, server ID, and network group
  • if the network group is invalid, CoreChatX disables cross-server features and explains the problem in the log
  • network groups must be lowercase and include a colon, such as corechatx:main or corechatx:network/main
  • invalid channel examples include CoreChatX:main, core chat x:main, corechatx, and corechatx:Main
  • deployment.bridges-allowed: false disables Discord and Telegram chat; a separate Discord console bot can still run through discord.console.*
  • deployment.network-features-allowed: false lets the server start in PROXY mode but disables all cross-server CoreChatX features
  • deployment.pending-pm-timeout-seconds cannot be lower than 5 seconds
  • with hooks.placeholderapi: true, most player-facing text supports PlaceholderAPI when the plugin and required expansions are installed
  • CoreChatX also registers %corechatx_player_nickname%, %corechatx_first_join_date% and %corechatx_messages_count% for other plugins when PlaceholderAPI is installed

4.2 chat.yml

Purpose:

  • public chat formatting
  • group-specific format overrides
  • mention token formatting
  • public and PM cooldowns

Current bundled default:

# Public chat formatting and moderation settings.

public-chat:
  enabled: true
  # Supported placeholders inside the format:
  # {plugin_prefix}, {channel_prefix}, {rank_prefix}, {player_name}, {player_nickname}, {message}
  # {player_name} is always the real Minecraft username.
  # {player_nickname} is the custom nickname when set, otherwise the real Minecraft username.
  # Layout inspired by the older NetworkChat proxy format:
  # prefix + player name + italic separator + processed message.
  # CoreChatX keeps its own default palette instead of copying the old colors verbatim.
  format: "{plugin_prefix} {channel_prefix}{rank_prefix}<white>{player_nickname}</white><dark_gray><italic>» </italic></dark_gray>{message}"
  # Optional group-specific format overrides keyed by LuckPerms primary group.
  # These are used only when channels.yml -> format is blank for the active channel.
  # Keys must match the LuckPerms primary group in lowercase.
  group-formats:
    owner: "{plugin_prefix} {channel_prefix}{rank_prefix}<white>{player_nickname}</white><dark_gray><italic>» </italic></dark_gray>{message}"
    admin: "{plugin_prefix} {channel_prefix}{rank_prefix}<white>{player_nickname}</white><dark_gray><italic>» </italic></dark_gray>{message}"
    mod: "{plugin_prefix} {channel_prefix}{rank_prefix}<white>{player_nickname}</white><dark_gray><italic>» </italic></dark_gray>{message}"
    vip: "{plugin_prefix} {channel_prefix}{rank_prefix}<white>{player_nickname}</white><dark_gray><italic>» </italic></dark_gray>{message}"
    default: "{plugin_prefix} {channel_prefix}{rank_prefix}<gray>{player_nickname}</gray><dark_gray><italic>» </italic></dark_gray>{message}"
  plugin-prefix: "<dark_gray>[</dark_gray><gradient:#79d6b8:#5aa9ff>Chat</gradient><dark_gray>]</dark_gray>"
  # Applied to non-global active channels such as local or staff.
  channel-prefix-format: "<dark_gray>[</dark_gray><white>{channel_name}</white><dark_gray>]</dark_gray> "
  fallback-rank-prefix: ""

mentions:
  enabled: true
  # Mention matching accepts both Steve and @Steve when the token matches a local or network-online player exactly.
  # If disabled, names are left as normal text and no mention notification logic runs.
  # The resolver accepts real usernames and custom plain nicknames; this format controls what the rendered mention displays.
  # {player_name} is the real Minecraft username. {player_nickname} is the visible nickname when set.
  token-format: "<#79d6b8>@{player_nickname}</#79d6b8>"

cooldowns:
  public:
    enabled: true
    seconds: 2
  private-messages:
    enabled: false
    seconds: 2

Format priority:

  1. channels.<id>.format
  2. public-chat.group-formats.<luckperms-primary-group>
  3. public-chat.format

Important notes:

  • {rank_prefix} works in every group-formats.<group> entry
  • if LuckPerms is not available, group-specific formats are skipped and CoreChatX falls back to the base format
  • if you already manage rank prefixes in LuckPerms, prefer {rank_prefix} over hardcoded titles in this file
  • PlaceholderAPI values can be used in most formats created by the server owner when support is enabled
  • text written by players does not run PlaceholderAPI values
  • mentions.token-format resolves {player_name} to the mentioned player's name
  • PlaceholderAPI values in mentions.token-format belong to the mentioned player, not the sender
  • for cross-server mentions, placeholders work only when their expansion supports players who are not on the local Paper server
  • negative cooldown seconds are treated as 0

  • discord.connection-messages and discord.event-messages can show joins, quits, first joins, deaths, and advancements without duplicates from every Paper server

  • use Paper discord.yml for the main bot only in STANDALONE mode; in PROXY mode it is only for optional local console bots with separate tokens

10. Practical Admin Notes

  • Keep messages.yml as the main wording file unless you actively need locale-specific overrides.
  • Use LuckPerms for rank titles/prefixes, and use CoreChatX for layout.
  • Keep group-formats keyed to the LuckPerms primary group in lowercase.
  • CoreChatX currently saves data in YAML; the SQL settings are reserved for future use.
  • Give every Paper server in a Velocity network a unique server-id.
  • If a custom permission in channels.yml, pings.yml, or privacy.yml is invalid, CoreChatX reports it and disables only that option. An invalid keyword permission disables only that keyword.
  • Deleting files such as playerdata.yml or mutedata.yml deletes live player or server data.
  • CoreChatX starts bStats on Paper and Velocity; opt-out is controlled by the platform-wide bStats files (plugins/bStats/config.yml on Paper and plugins/bStats/config.txt on Velocity), not by a CoreChatX config key.

Recommended setup:

  • restart after changing config.yml -> deployment.* or Velocity network-channel values
  • define each chat format in one place instead of repeating it across several plugins
  • configure Discord and Telegram access for each CoreChatX channel in channels.yml
  • use PlaceholderAPI only in formats created by the server owner
  • keep Discord and Telegram tokens private and never paste them into screenshots, public logs, or support messages
  • back up saved data before manually editing player settings, mutes, ignores, or active channels

11. Troubleshooting Quick Reference

Startup banner does not appear

Check that the Paper jar is installed on Paper and the Velocity jar is installed on Velocity. Also confirm Java 21 is in use and read the startup log for the loading error. A successful start prints the CORECHATX banner with the version and platform.

/corechatx reload does not apply a change

These settings require a restart:

  • deployment.mode
  • deployment.server-id
  • deployment.network-channel
  • every setting in Velocity velocity-config.properties, velocity-discord.yml, and velocity-messages.yml

Restart the affected Paper server or Velocity after changing any value listed above.

Network messages do not cross servers

Verify:

  • every Paper server uses deployment.mode: "PROXY"
  • every Paper server has a unique deployment.server-id
  • every Paper server has deployment.network-features-allowed: true
  • every Paper deployment.network-channel is listed in Velocity velocity-config.properties -> network-channel
  • the Velocity jar is installed and started
  • at least one test player is connected while you test cross-server chat

Also check that the channel itself is configured as scope: NETWORK. In standalone mode, NETWORK channels fall back to normal local chat behavior.

Discord or Telegram messages do not send

Verify:

  • deployment.bridges-allowed: true
  • the Discord or Telegram enabled value is true
  • the CoreChatX channel has export-to-bridges: true
  • tokens, channel ids, chat ids, and topic ids are valid
  • the route points to the intended Discord channel or Telegram chat

In PROXY mode, CoreChatX sends each network message to Discord or Telegram only once.

Discord or Telegram inbound does not appear in Minecraft

Verify:

  • incoming messages are enabled for that integration
  • the incoming route points to an existing CoreChatX channel
  • the integration is configured in the correct place: Paper for standalone, Velocity for Discord in proxy mode, and Paper for Telegram
  • for Discord, the bot has the required Message Content intent when message content is needed
  • for Telegram, the token, chat ID, and optional topic ID are correct

Removing a Discord whitelist role does not disconnect the player

Verify:

  • the account-linking role gate is enabled for the affected network group
  • the bot has the privileged Server Members Intent enabled in the Discord Developer Portal
  • the bot was restarted after enabling that intent
  • guild-id and role-ids identify the expected guild and numeric Discord roles
  • the Minecraft account is linked to the Discord member being changed

CoreChatX checks the player's current Discord membership and listens for role or server-membership changes. Losing the final allowed role, leaving, being kicked, or being banned disconnects the linked player and blocks reconnection until the requirement is met again.

PlaceholderAPI placeholders do not render

Verify:

  • PlaceholderAPI is installed on that Paper server
  • hooks.placeholderapi: true
  • the expansion required by that placeholder is installed and working
  • the setting supports PlaceholderAPI and belongs to a server-created format

Text written by players does not run PlaceholderAPI values. In a mention format, placeholders use information from the mentioned player.

Mentions do not notify players

Verify:

  • mentions are enabled in chat.yml
  • the channel has allow-mentions: true
  • the target player allows mention notifications
  • ignore and privacy settings are not blocking the notification
  • permissions and staff bypass rules are configured as intended

ChatItems work locally but not across servers

Verify:

  • Paper and Velocity use the same CoreChatX group
  • ChatItems are enabled for the channel
  • the shared item is within the configured cross-server size limits
  • the preview has not expired
  • network-features-allowed is true on participating Paper servers

CoreChatX retrieves the full preview from the Paper server where it was shared when another player clicks it. If it is unavailable or expired, the player receives the normal expired-preview message.

Discord ChatItem images do not render

Verify:

  • chatitems.yml -> discord-images.enabled: true
  • the Minecraft source channel allows ChatItems and bridge export
  • the sender has the configured token permission
  • vanilla assets can be downloaded or already exist in the local cache
  • optional resource-pack paths resolve from plugins/CoreChatX/
  • the configured image count and ChatItem size limits allow the preview

Use /corechatx itemcache status to check whether textures are ready. If Discord cannot create the image, the Minecraft ChatItem preview still works.

Chat bubbles are missing

Verify:

  • chat bubbles are enabled in chatbubbles.yml
  • the player has the bubble permission
  • the player has not disabled bubbles in settings
  • the channel has allow-chat-bubbles: true
  • the message passed normal CoreChatX checks

In PROXY mode, bubbles stay on the Paper server where the sender is playing.

A config permission warning appears

Check dynamic permission nodes in:

  • channels.yml
  • pings.yml
  • privacy.yml
  • keywords.yml
  • chatitems.yml

An invalid permission disables only the affected option or keyword. You do not need to delete the whole configuration file.

A saved data file looks wrong

Stop the server, back up the file, and then inspect it. Files such as playerdata.yml, channeldata.yml, ignoredata.yml, mutedata.yml, and discordlinks.yml contain live data. Editing or deleting them changes saved player or server information.

12. Final Setup Checklist

Before opening a server to players:

  • start every Paper server once and confirm the CORECHATX startup banner
  • if used, start Velocity once and confirm its CORECHATX startup banner
  • run a normal public chat message
  • run a channel switch and verify send/receive permissions
  • test a configured channel shortcut in switch and one-shot send forms
  • test permanent and timed /hidechannel, then /unhidechannel
  • test /msg and /reply
  • disconnect/rejoin a PM participant and confirm the previous-session reply target is gone
  • test /nick, /realname, and nickname formatting permissions
  • test mentions, custom pings, and notification toggles
  • test the configured public-chat ignore mode and one per-channel override
  • test one PlaceholderAPI value in a server-controlled template
  • test one keyword hover/click action
  • test one ChatItem preview locally
  • if Discord ChatItem images are enabled, test an image plus its item-inspection selector
  • in PROXY mode, test one network channel message from each Paper server
  • in PROXY mode, test one cross-server private message
  • in PROXY mode, test one cross-server ChatItem preview
  • test Discord outbound and inbound if enabled
  • test Discord link/unlink, nickname sync, player list, event/connection mirrors, descriptions, and status messages for every feature you enable
  • if Discord role admission is enabled, remove the final allowed role while the player is online and confirm disconnect plus blocked reconnect
  • test Telegram outbound, inbound, and topic routing if enabled
  • test mute, mutechat, clear chat, social spy, ignore, and PM toggle behavior
  • run /corechatx reload after a harmless wording change and confirm it applies
