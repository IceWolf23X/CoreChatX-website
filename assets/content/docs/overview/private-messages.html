Private messaging is part of the same communication system as public chat.

Included tools:#

  • direct messages
  • reply command
  • social spy
  • ignore controls
  • PM toggle
  • delivery feedback
  • cross-server private messages

The result is a PM system that understands the rest of the plugin: privacy, moderation, network routing, formatting, and player settings all live in the same ecosystem.

Cross-server PM requests use bounded correlation and reject overlapping work instead of accumulating an unbounded queue. A forwarded PM consumes its configured cooldown once accepted for routing, even if the remote destination later rejects it or the request times out. A timeout does not prove that the remote operation was cancelled.

/msg and /reply share token rendering on standalone Paper and proxy backends: ChatItems, permission-controlled formatting, keywords and participant mentions. Mention text resolves only the sender or recipient; mention and custom-ping notifications target only the admitted recipient, never the sender, unrelated players or SocialSpy viewers. The receiving backend rechecks the recipient's permissions and preferences. Custom pings still require the sender's Bukkit use-permission; bypass-toggle can override only the recipient's ping toggles. The normal PM bell remains independent.

PMs apply the configured anti-repeat and anti-caps rules and their existing bypass permissions. PM repeat history is separate from public chat and records only accepted local deliveries or successful remote delivery results; quit, reload and shutdown clear it. Remote rejection does not enter repeat history, although a configured cooldown is consumed when transport accepts publication.

Once target text is delivered, reply targets, moderation history, cooldown state and remote delivery confirmation are established before optional notifications. A failed sound, ping, SocialSpy copy or console log does not undo delivery or interrupt the remaining effects. Diagnostics are bounded and do not log private text.
